## Non-negotiables (read before doing anything else)

1. **The prototype phase needs UI/UX only — no working code, no back-end.** Figma, Canva, paper sketches, or a static HTML page are all equally acceptable. Building working logic now earns **zero** extra credit and isn't required until/unless the team is selected as a finalist.
2. **Ideation + Impact = 45% of the total score** — more than Design (10%) and Presentation (15%) combined. Documenting the *thinking* (ideas explored and dropped, mentor feedback acted on) matters more than how polished the mockup looks.
3. **Dead ends are worth points.** Every idea considered and discarded should be recorded, with why.
4. **At least one mentor session is effectively mandatory** — skipping it costs 7% of the Ideation score (Mentor Consultation & Feedback Integration).
5. Everything for the submission is linked from the **GitHub repo's README.md** — the repo doesn't need to contain working code at this stage, just links (video, design, ideation assets).
6. Video presentation: **3–5 minutes, YouTube, set to unlisted.**
7. Only **one** problem statement may be chosen — this team has chosen **Stress & Workload Manager**.

## How to use these files

- Before writing copy, designing a screen, or scoping a feature: check `03-judging-rubric.md` — does this move a specific score band up?
- Before writing the actual submission: use `04-submission-requirements.md` as the section-by-section checklist, and fill in the real `reference/Submission Template.docx`.
- For the current state of the actual UI/prototype: `05-figma-prototype.md` (screen-by-screen description) and the live Figma link inside it — always treat Figma itself as the source of truth, this file is just a snapshot summary.
- For anything about deadlines, mentorship booking, or event logistics: `01-competition-rules.md`.
- For the exact wording of the problem we're solving: `02-problem-statement.md`.
